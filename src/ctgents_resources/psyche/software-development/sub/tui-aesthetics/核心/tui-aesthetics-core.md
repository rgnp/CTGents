# TUI Aesthetics 核心认知框架

> 版本: 0.4 | 更新: 2026-07-13
> 定位: 审美设计在终端介质中的特化；通用审查流程由父 Psyche 的 `review-interface` Skill 执行

## 一、判断增量

终端是等宽字符网格和持续变化的文本时间线。TUI 的美感来自信息层级、稳定布局、输入连续性与降级可靠性，而不是模拟网页装饰。

## 二、Competency Questions

1. 在 80×24 和真实终端宽度下，主要信息和输入仍然可用吗？
2. 对齐是否基于显示宽度而非字符串长度，宽字符和 ANSI 样式是否安全？
3. 流式输出、spinner、状态栏和历史内容是否争抢同一区域？
4. 颜色减少或动画关闭时，语义是否仍可辨认？
5. Widget 数量、重绘范围和滚动策略是否造成可感知延迟？

## 三、五个不动点

1. **字符网格是物理边界**：换行、宽字符、控制序列和终端尺寸必须进入设计判断。
2. **稳定优于炫动**：动态反馈应占据稳定区域，不让历史、输入框和阅读位置持续跳动。
3. **性能属于审美**：输入延迟、闪烁和整屏重绘会直接破坏完成感。
4. **双路径保持语义一致**：富终端、降级终端和纯文本路径可以不同样，但不能丢失状态和含义。
5. **密度服务扫描**：通过对齐、空白和有限强调建立节奏，不用大量边框和色彩切碎内容。

## 四、负面知识

- 用网页盒模型直觉设计字符网格。
- 按字符串长度对齐，忽略显示宽度和 ANSI 序列。
- 每个状态都创建独立 Widget，导致树过深和重绘过多。
- spinner、流式输出和状态消息让内容上下跳动。
- 颜色承担唯一语义，没有无色降级。

## 五、组合契约

本 Psyche 同时依赖 `software-development` 与 `aesthetic-design`：前者审计状态和性能，后者审计层级与表达。需要实际审查时使用 active `aesthetic-design` 所拥有的 `review-interface` Skill，并选择 `medium=tui`。
