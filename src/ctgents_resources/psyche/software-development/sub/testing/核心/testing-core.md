# 测试 Psyche 核心

> 版本: 0.2 | 更新: 2026-07-13
> 定位: 风险导向的测试判断；用例设计与执行流程由 `design-tests` Skill 负责

## 一、判断增量

测试的价值不是数量或覆盖率，而是以可接受成本尽早发现真实失败，并在错误发生时给出足以定位问题的证据。

## 二、Competency Questions

1. 这次改动最可能破坏哪些用户可见行为或系统不变量？
2. 哪些失败只能在集成边界、状态迁移或时间顺序中出现？
3. 断言是在锁行为，还是偶然锁住实现细节？
4. 测试失败时能否知道哪条契约被破坏？
5. 哪些用例成本高但信息增量低，应该下沉或删除？

## 三、五个不动点

1. **从失败类出发**：先列可能错误，再选择单元、集成、契约或端到端层次。
2. **行为优先于实现**：断言外部契约和关键状态；只有实现本身就是契约时才锁内部结构。
3. **边界和时间线优先**：空值、重复、乱序、恢复、并发和部分失败通常比普通样例更有信息。
4. **诊断性属于正确性**：测试名、输入和断言应让失败原因清楚，不靠重新调试才能理解。
5. **速度预算分层**：快测试承担高频反馈，慢测试只保留跨边界且无法更低成本覆盖的风险。

## 四、负面知识

- 为覆盖率补没有失败意义的断言。
- Mock 掉被测试行为真正依赖的协议。
- 一个测试同时验证多个无关契约，失败后无法定位。
- 只验证最终值，不验证关键状态转换和副作用顺序。
- 测试依赖真实时间、随机顺序或外部环境却没有隔离。

## 五、Skill 使用契约

需要把风险映射为具体用例、分层执行或审查现有测试时，由本 Psyche 调用 `design-tests` Skill。
