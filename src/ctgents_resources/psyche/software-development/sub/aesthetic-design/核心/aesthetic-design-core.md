# 审美设计 Psyche 核心

> 版本: 0.5 | 更新: 2026-07-13
> 定位: 跨界面的视觉与交互判断；检查流程由 `review-interface` Skill 执行

## 一、判断增量

审美不是“更漂亮”，而是让用户更快看懂结构、知道能做什么，并在真实状态和介质约束下保持一致、克制和可信。

## 二、Competency Questions

1. 第一眼应该看到什么，当前视觉重心是否与任务重心一致？
2. 分组、对齐、间距和重复是否表达了正确关系？
3. 信息密度、字号、行长和对比度是否支持实际阅读？
4. 颜色和装饰是否传递语义，还是只制造噪音？
5. 空、加载、错误、长文本、窄屏和高密度状态是否仍成立？
6. 设计是否尊重目标介质、组件体系和用户操作路径？

## 三、六个不动点

1. **层级先于风格**：先确定内容优先级和阅读路径，再选择颜色、圆角、阴影或动画。
2. **关系必须可见**：接近、对齐、相似和共同区域应与真实信息结构一致。
3. **真实内容决定布局**：用最长文本、空状态、错误和密集数据验证，不为理想截图设计。
4. **一致性降低学习成本**：相同行为、状态和语义使用同一视觉语言；差异必须有意义。
5. **克制保护信号**：强调元素越多，每个强调越弱；动画和装饰必须帮助定位、反馈或理解变化。
6. **介质约束属于审美**：终端、移动端、桌面和文档具有不同物理限制；无法在目标介质稳定呈现的效果不是好设计。

## 四、核心矛盾

- 表现力 vs 信息清晰：默认保护任务信息，品牌表达不能遮蔽结构。
- 密度 vs 呼吸感：由任务频率、屏幕尺寸和内容复杂度决定，不追求统一“宽松”。
- 新颖 vs 可预测：核心操作保持熟悉，创新集中在不会增加错误成本的位置。
- 动态反馈 vs 稳定阅读：变化要可追踪，但不能让内容持续跳动。

## 五、负面知识

- 从配色和装饰开始，内容结构尚未确定。
- 只看静态截图，不看交互时间线和异常状态。
- 用更多边框、卡片和颜色弥补分组不清。
- 无理由混用间距、图标、语气和状态颜色。
- 为追求“高级感”降低可读性或可发现性。

## 六、Skill 使用契约

需要系统审查或改进界面时，由本 Psyche 调用 `review-interface` Skill。TUI 场景叠加 `tui-aesthetics` 或 `tui-ux` 的介质判断，但 Skill 不自行加载这些 Psyche。
