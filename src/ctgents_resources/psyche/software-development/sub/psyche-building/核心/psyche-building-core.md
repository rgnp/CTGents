# Psyche Building 核心认知框架

> 版本: 0.8 | 更新: 2026-07-13
> 定位: 判断 Psyche 是否值得构建、是否改变认知、是否可验证；构建流程由 `build-psyche` Skill 执行

## 一、判断增量

Psyche 不是领域知识摘要或长提示词。它是一组能稳定改变判断的认知约束：加载后，Agent 会看见此前遗漏的维度，作出可解释、可复核的不同判断。

## 二、Competency Questions

1. 不加载它时，具体会漏掉什么判断？
2. 它应该稳定回答哪些 Competency Questions？
3. 哪些准则是稳定认知，哪些只是流程或时变事实？
4. 每条关键判断的证据来源和置信层级是什么？
5. 它与父 Psyche 的增量、边界和冲突是否明确？
6. 用什么行为样例能证明加载后更好，而不是仅输出更多术语？

## 三、六个不动点

1. **判断增量是存在理由**：不能说明加载前后决策差异，就不该新建 Psyche。
2. **先定义问题，再收集知识**：Competency Questions 决定范围；材料数量不能替代范围判断。
3. **Psyche、Skill、Knowledge 分层**：稳定判断进 core，可重复步骤进 Skill，事实和时变共识进 Knowledge。
4. **浓缩是理解测试**：core 只保留不可替代的判断准则、失败模式和边界；删掉不改变判断的内容。
5. **证据强度匹配措辞**：实战经验、单一来源、跨来源共识和当前推测不能使用同样确定的口吻。
6. **行为验证先于自我感觉**：至少用正例、反例、边界例和不相关任务测试是否正确触发和产生目标增量。

## 四、质量四维

- **功能覆盖**：能否回答声明的 Competency Questions。
- **结构纯度**：core 是否只含认知，父子增量和 Skill/Knowledge 边界是否清楚。
- **可演进性**：来源、版本和更新触发是否可追踪，时变事实是否已外置。
- **边界意识**：知道何时不适用、与谁冲突、哪些结论仍未知。

## 五、负面知识

- 把资料堆成 core，没有蒸馏因果和判断准则。
- 一看到主题词就创建或加载 Psyche。
- 把完整操作手册写进 Psyche，或让 Skill 反向加载 Psyche。
- 用“有 knowledge 目录”代替验证知识质量。
- 用条目齐全度代替行为改变。
- 只做成功案例，不测误触发、冲突和边界。

## 六、Skill 使用契约

需要新建、重构或评估 Psyche 时，由本 Psyche 调用 `build-psyche` Skill。Skill 负责测绘、证据整理、蒸馏、Manifest 更新和评测步骤；本 core 决定什么结果才算合格。
