# 论文深读 — 操作流程

> 加载: always | 定位: 操作层执行序列
> 关联: paper-deep-read psyche P1-P5（认知框架层的对应）

---

## 流程总览

```
P0 → D0 → P1 → P2 → P3 → P4 → P5
  │     │     │     │     │     │     │
 扫描  不满   论证   定位   激活   追问   输出
```

每一阶段是下一阶段的前提。不可跳步。D0 为可选步骤——开启 `dissatisfaction` 模式时激活；默认关闭（仅 P0→P1→…→P5）。

---

## P0 · 快速扫描（建立全局感）

目标：5 分钟内形成"这篇论文大概在干什么"的整体判断。

操作：
1. 读标题 + 摘要
2. 扫图 1（overview/teaser figure）——这通常解释了整个 pipeline
3. 读结论最后一段
4. 扫实验表格的关键数字

输出（口头告知用户）：
- 一句话核心贡献
- 论文类型（research/survey/theory/position）
- 推断的 domain
- 是否值得继续深读（附带理由）

深度控制：
- 如果 depth=skim，P0 就是终点。输出后询问是否要切到 normal/deep
- 如果 depth=normal/deep，P0 是起点，直接进 P1

---

## D0 · 不满反推（可选，dissatisfaction 模式开启时激活）

目标：在读到作者动机之前，从方法论反推他到底对什么不满。

操作：
1. 只读方法论——不看 Introduction / Motivation / Related Work
2. 定位作者改了什么：他改了系统的哪个环节（表示？预测步数？训练目标？评估方式？）
3. 反推不满：如果原来的做法没问题，他为什么要改这个环节？把这个"原来的做法"具体说出来——不是"重建目标不对齐"，而是"训 WM 时 MSE 看着低但规划器拿这个表示做决策时撞了"。
4. 对照 `references/dissatisfaction-patterns.md` 中的常见不满模式：这个不满属于哪一类？
5. 对答案：读 Introduction/Motivation，看作者自己怎么说。记录反推正确/偏差/遗漏的地方。

约束：
- 不先读 intro。如果已经读了，跳过 D0 直接进 P1。
- 不满必须是具体现象而非领域方向——"前后帧检测框位置突变"而非"时序一致性不足"。
- 如果方法论信息不足以反推不满（如论文写法把 intro 和 method 交织），诚实标注并直接进 P1。

---

## P1 · 论证审计（Toulmin 七问）

目标：精确定位论文的核心论证结构——不只是"它做了什么"，而是"它为什么声称这样做是对的"。

七问（逐条执行，不可省略）：

1. **Claim** — 论文的核心断言是什么？
   - 通常在主 contribution 段。是一项 claim 还是多项？
   - 「本文声称 X 方法在 Y 任务上优于 Z」

2. **Grounds** — 凭什么这么说？
   - 实验数据？理论推导？消融实验？
   - 关键实验的条件：数据集、baseline、指标、seed

3. **Warrant** — 为什么这些实验数据能支持这个 claim？
   - 这是最容易被跳过的——"性能好"不自动等于"方法好"
   - 检查：实验条件是否公平？指标是否全面？baseline 是否合理？

4. **Backing** — warrant 背后有什么更根本的理论/共识支撑？
   - 「因为 attention 能捕获长程依赖」（如果没有验证 attention 确实捕获了，这就是 gap）

5. **Rebuttal** — 作者自己承认了什么限制？
   - 查 limitation/failure case/discussion
   - 如果完全没有——这是信号，不是好消息

6. **Qualifier** — claim 的适用范围是什么？
   - 只在特定数据集上？特定设置下？特定假设下？
   - 把这论文的做法搬到用户的场景行不行？

7. **Unexamined** — 论文没有触及但应该触及的问题？
   - 这是问题的来源——"为什么他们没有..."

**输出（内部）**：Claim map + warrant 审计记录

---

## P2 · 领域地图定位

目标：把这篇论文放到用户的领域知识网络里。

操作：
1. 查 `knowledge/autonomous-driving/blocks.md`，确定该论文占据/挑战了哪个 block
2. 查已读论文卡片（`knowledge/paper/`），找最相关的 2-3 篇对比
3. 判断关系：confirm / contradict / extend / orthogonal
4. 如果论文引入新概念，更新 terminology-ledger

**输出（内部）**：领域定位（block × 关系 × 相关论文）

---

## P3 · 跨知识网络激活

目标：这篇论文触发了之前读过的哪些论文？激活了什么新的连接？

操作：
1. 在已读论文中搜索共享的技术组件（如相同 backbone、相同 loss、相同数据集）
2. 识别矛盾：两篇论文用相似方法得到不同结论？条件差异是什么？
3. 识别空白：这篇论文做了 X，但没做 Y——哪篇论文做了 Y？

**输出（口头）**：激活的连接（2-5 条），附来源论文

---

## P4 · 追问式解释

目标：按用户的理解习惯重新组织内容——追问驱动而非复述驱动。

操作：
1. 不是"本文做了 A、B、C"，而是"本文要解决什么问题？→ 之前的方案为什么不行？→ 本文的关键 trick 是什么？→ 这个 trick 为什么管用？→ 什么时候不管用？"
2. 每个技术决策追问"如果不这样做会怎样？"
3. 用类比解释不直观的设计

**输出（口头）**：追问链式解释

---

## P5 · 结构化输出

目标：落盘为可复用的论文卡片。

输出格式（写入 `knowledge/paper/{name}.md`）：

```markdown
# {论文标题}
- arXiv: {id} | 年份: {year} | 会议: {venue}
- 一句话贡献: {one-liner}
- 领域定位: {block} / {relation}

## 论证结构（Toulmin）
- Claim: {核心断言}
- Grounds: {关键实验条件+数字}
- Warrant: {为什么实验支持 claim}
- Rebuttal: {作者自认限制}
- Unexamined: {我们的发现}

## 积木提取
- 可复用技术组件: {component descriptions}
- 搭法模式: {combination pattern}

## 矛盾/缺口（→问题库）
- {具体矛盾描述}

## 与已读论文的关系
- {论文名}: confirm/contradict/extend，原因

## 注意事项
- 用户场景: {算力/数据/开环闭环约束检查}
```

### 输出后的收尾

- **depth=normal**: P5 输出后询问用户是否需要深入某个方面
- **depth=deep**: P5 输出后自动追加 warrant 逐条审计 + 引用追溯
