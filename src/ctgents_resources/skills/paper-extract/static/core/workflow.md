# 论文榨干 — 操作流程

> 加载: always | 定位: 操作层执行序列
> 三层流水线：评→取→用。每层有判断问题，不是步骤清单。

---

## 前置检查

1. 确认已拿到论文正文（PDF→text 或 arxiv HTML）
2. 如果 paper-deep-read card 不存在或过旧 → 先走 paper-deep-read（激活 deep-read Skill 或手动审计）
3. paper-deep-read 产出作为审计层输入，不重复做

---

## 阶段一：评 — 审计层（判断这篇成色）

从 paper-deep-read 的结果中提取，结合原文验证。要回答的不是「维度填了没」，而是：

- 这篇论文**实际在解决什么问题**？（≠ 作者声称的。看实验设计和省略的对比）
- 论证链**最弱一环**在哪？（warrant 审计——哪个推理跳跃最致命）
- **如果我是 reviewer**——最致命的两个问题是什么？作者 rebuttal 最怕被问到什么？
- 这篇**暴露了我什么不懂的**？（→ 知识债务：需要补的前置、需要追的引文、需要 learn 的概念）

---

## 阶段二：取 — 提取层（拆出可复用资产）

以原文为唯一事实来源。要回答：

- 这篇有**什么我能直接抄的技术组件**？（→ 积木库：架构/trick/训练策略/损失函数，每个拆成「是什么+在什么条件下管用+从哪里抄」）
- 这篇和**已读论文在什么地方互斥**？（→ 矛盾清单：前提层/方法层/结论层。不只是「A 说 X，B 说非 X」——还有「A 和 B 用不同机制得到相似结果」这种矿脉）
- 这篇和**同问题的其他解法比**——分叉在哪？各自的边界是什么？能不能调和？（→ 差分诊断）
- 这篇的**实验范式能复用吗**？（benchmark 组合、metric 选择、消融设计、评测协议）
- 这篇在**领域坐标系**的什么位置？往哪个方向推了？（显式生成←→潜在建模、规划导向←→仿真导向）
- 这篇的**写作有什么值得学/不值得学的**？（命名、叙事、Figure 设计、如何制造 urgency）
- 这篇**改写了什么前提**？（旧前提→新前提，影响力判断）
- 这篇在**时间线上**是开端/延续/收尾/孤立？

---

## 阶段三：用 — 决策层（拿这篇怎么办）

聚合审计层和提取层，形成决策判断。要回答：

- **即战力判定**：现在能跑？能改？能引？（三级判定，每级说清条件）
- **复现可行性**：能复现吗？缺什么？最大 blocker 是什么？
- **用户决策**：
  - 方向匹配度（边界内/外/灰区）
  - 单人 A40 可行性（train/test/extend）
  - 最小可发表单元（workshop short paper？对比实验？消融扩展？）
  - 跟的风险（赛道拥挤度/是否红海/大组碾压）
  - 如果不跟，带走什么 insight/积木
- **一句话 takeaway**：从用户视角，读完带走什么（≠ 作者的 claim）

---

## 深度控制

### depth=lite（默认）

只走阶段一 + 阶段二的精简（矛盾定位 + 一句话 takeaway）。目标是判断：**这篇值不值得跟。**

lite 跑完后 agent 必须显式判断：**够格切 full 吗？** 判断标准：
- 在用户边界内？不是直接排除的路线？
- 有可提取的积木？不只是「指标涨了」的工程报告？
- 有可挖掘的矛盾？和已读论文存在值得追问的张力？

三个问题任何一个回答「是」，切 full。

### depth=full

全部三阶段。纸面时间预计 15-30 分钟，实际取决于论文复杂度。

## 产出分散规则

不新建一个「论文拆解报告.md」。产出按类型分散：

| 产出类型 | 落盘位置 | 对应维度 |
|----------|---------|---------|
| 论证审计 | paper-deep-read card（已有则不重复） | D1/D4/D6/D9/D14/D15 |
| 积木 | `knowledge/blocks/<component-slug>.md` | D2 |
| 矛盾/差分诊断 | `knowledge/domain-maps/contradictions-<domain>.md`（追加新条目） | D3/D16 |
| 实验范式 | `knowledge/methods/experiment-patterns.md`（追加） | D5 |
| 写作技巧 | `knowledge/methods/writing-patterns.md`（追加） | D7 |
| 领域坐标/时间线 | `knowledge/domain-maps/<domain>.md`（更新坐标系） | D10/D17 |
| 阅读状态 | `knowledge/paper/reading-tracker.md`（更新） | D11/D13 |
| 用户决策 | 口头报告（不在文件里替用户选） | D8/D12 |

### 写前检查

- 积木 → 先查 `knowledge/blocks/` 是否已有类似组件，避免重复
- 矛盾 → 先读 `knowledge/domain-maps/contradictions-*.md`，确认不重复
- 范式 → 先读 `knowledge/methods/experiment-patterns.md`，只在有新模式时追加
