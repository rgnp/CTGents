# 设计与审查测试

## 前置条件

- `testing` Psyche 必须 active。
- 先读取被测行为、调用边界和现有测试，不根据函数名臆测契约。

## 工作流

1. 写出改动前后必须成立的行为契约。
2. 列出最可能失败的状态、边界、顺序和外部协议。
3. 为每个失败类选择能最小成本观察它的测试层次。
4. 复用项目现有 fixture 和风格，避免建立平行测试框架。
5. 每个测试只锁一个紧密契约；名称描述条件和结果。
6. 先运行最小相关集合，失败时确认是产品缺陷、测试假设错误还是环境问题。
7. 高风险修改再扩大到模块和全量回归。

## 操作轴

- `design`：优先补真实失败类，包括至少一个边界或恢复路径。
- `review`：检查价值、脆弱性、重复、速度和诊断性，不以覆盖率单独判好坏。
- `triage`：先稳定复现，再缩小输入、边界和时间顺序；不要直接放宽断言让测试通过。

## 完成标准

测试在错误实现上会失败，在正确实现上稳定通过；失败消息能指出被破坏契约，并且没有不必要地锁死内部实现。
