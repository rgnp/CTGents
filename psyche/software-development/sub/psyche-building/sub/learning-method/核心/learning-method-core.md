## 一、认知姿态

1. **学透 = 能找出问题** — 只看懂它做了什么不算学透。能说出它代码/逻辑上的问题、边界情况、反直觉设计，才算学透。
2. **不带问题去读等于没读** — 打开一个项目前先问自己：我要从它身上学到什么？它什么地方可能有问题？
3. **代码本身是正文** — README、架构图、摘要都是索引。真正的内容在代码全文/论文正文里。

## 二、深度阅读检查清单

### 项目类

读源码全文（不只是目录结构和 README），按顺序过：

```
① 入口和包结构
   - 入口在哪？模块怎么划分的？
   - 每个模块的核心职责是什么？

② 核心数据流
   - 核心循环/流程在哪？
   - 数据怎么流进来的？怎么出去的？
   - 关键的状态转换是什么？

③ 关键决策
   - 架构上最重要的几个选择是什么？
   - 留下了什么 trade-off？
   - 为什么这么设计而不是另一种方式？

④ 找问题（★ 学透的标志）
   - 边界情况没处理？（空值、异常、并发）
   - 静默数据丢失？（成功但不通知）
   - 用异常做控制流？
   - 安全漏洞？（路径穿越、输入校验）
   - 竞态条件？
   - 错误处理是否完备？

⑤ 对比与自检
   - 和我们系统的对应模块比，有什么差异？
   - 我们能从他身上学到什么？
   - 我们能不能避免他的错误？
```

### 论文类

```
① 读全文（不是只读摘要）
② 三问：
   - 解决了什么前人没解决的？
   - 隐藏假设是什么？
   - 留下了什么新问题？
③ 与已有 knowledge/ 交叉验证：支持/矛盾/补充
```

### 关口

- 能说清：它核心思想是什么？它最好的地方是什么？它的问题是什么？
- 如果只能说"它做了XXX"说不出"它有什么问题" → 读得不够深，继续找
- **至少找到一个反直觉发现才算学透**

---

## 三、负面知识

- 只读 README/摘要就总结 = 知道了存在，没学会
- 只看架构图就下结论 = 细节全在代码里
- 只读一篇综述就说懂了 = 综述是索引，不是知识
- 读了不落盘 = 下一会话从头查
- 学了不找问题 = 只消费不批判，没真懂
