## 一、认知姿态 — 构建 Psyche 时的九个不动点

1. **质量是系统性的，不是清单检查** — 好 Psyche 不是"要素齐全"而是"有认知状态"。加载后是否改变了思维方式？——这是唯一的终极标准。要素清单（认知姿态/判断准则/负面知识/边界……）是手段不是目的。[→知识卡片: empirical]

2. **先问 Competency Questions，再建 Psyche** — Ontology 101 的核心方法：构建前先列出"这个 Psyche 应该能回答什么问题"。范围由问题界定，不凭感觉。能回答这些问题的 Psyche 就是够好的 Psyche。[→知识卡片: ontology-101]

3. **🔴 双轨制是不可跳过的铁律** — 知识库是 psyche 的肉身，核心只是索引。没有 knowledge/ 就没有 psyche。核心和 knowledge/ 必须同时构建，核心永远后于知识库。没有卡片支撑的判断在核心中只能标 L3/L4，不能享受 L1/L2 的置信度。这不是加工作量，是保证每个判断可追溯。[→知识卡片: empirical + KE-practices]

4. **四维质量标准决定判断方向** — 好 Psyche 由四个核心维度判定（见第二节），构建中的每一步决策都在解答"这样能提高哪个维度的质量"。[→知识卡片: gangemi-gomez + oquare]

5. **浓缩力是核心能力** — 一个领域可能有 100 篇论文、1000 条经验，但 Psyche 核心只能浓缩到 1-2 页。蒸馏不是"挑重要的"，而是"找出因果结构"——知道什么可以拿掉而不破坏认知状态。做不到浓缩说明理解不够深。[→知识卡片: empirical]

6. **知道边界和知道内容同样重要** — reading-gaps 不是"还没做"的待办清单，而是"我知道这里我不知道"的主动声明确认。有清晰的边界比模糊的全覆盖更有价值。[→知识卡片: empirical]

7. **每个 Psyche 都必须能自检** — 封闭问题（"我这个 Psyche 好不好？"）没有标准答案。但开放自检（"我的 Judgments 有来源吗？边界清楚吗？能回答 Competency Questions 吗？"）每个都是可回答的。[→知识卡片: empirical + OQuaRE]

8. **工作量必须按阅读量拆解估，不套模板** — 引导流程 Step 3 里的 L1/L2/L3 时间估计是参考值，不是数学公式。每次构建前先拆实际阅读量：外部领域（10-30 篇论文）vs 元领域（实证经验为主）vs 技术栈（文档为主）。模板数字照填 = 规划谬误。[→知识卡片: empirical]

9. **知识库健康度是 psyche 的"体检指标"** — 核心封面上的知识库健康度（🟢🟡🔴）不是装饰，是快速判断 psyche 可信度的第一眼标准。🟢=判断有来源，🟡=部分判断靠记忆需要补卡，🔴=没有知识库这个 psyche 不可用。执行底线三条：①knowledge/目录存在 ②代表性论文有对应卡片 ③核心判断可追溯到具体文件。任何一个不满足，psyche 就不算"可用"。[→构建协议总则]

## 二、Psyche 质量框架 — 四维评估体系

融合 OQuaRE (8特性) + Gangemi (3维度) + Gomez-Perez (4标准) + 实证经验，提炼为 Psyche 特有的四维：

### 维度一：功能覆盖（Functional Coverage）
*对应: OQuaRE 功能适配性 / Gangemi 功能维度 / 完整性标准*

| 子维度 | 定义 | 自检问题 |
|--------|------|---------|
| 范围准确 | 覆盖范围与 Competency Questions 匹配 | 这个 Psyche 能回答它承诺的问题吗？ |
| 判断可操作 | 准则不是知识清单，是可做的决策 | 别人能用这条判断做实际决定吗？ |
| 来源充分 | 每条判断有知识库支撑 | 我能在 5 分钟内找到这条判断的原始依据吗？ |

### 维度二：结构质量（Structural Quality）
*对应: OQuaRE 结构特性 / Gangemi 结构维度 / 一致性+简洁性标准*

| 子维度 | 定义 | 自检问题 |
|--------|------|---------|
| 一致性 | 判断准则不自相矛盾 | 两条准则放在一起会不会给出相反的建议？ |
| 简洁性 | 无冗余判断 | 去掉这条判断会丢失什么信息？ |
| 层次清晰 | 认知姿态→领域地图→判断准则有逻辑递进 | 新手能从上到下读懂结构吗？ |
| 缠结度低 | 概念间关系不过度交织 | 改一个概念会影响多少个其他概念？ |

### 维度三：可演进性（Evolvability）
*对应: OQuaRE 可维护性 / 可扩展性标准*

| 子维度 | 定义 | 自检问题 |
|--------|------|---------|
| 可扩展 | 能加子 Psyche 而不破坏父框架 | 加了子 Psyche 后，父 Psyche 的判断是否需要大量修改？ |
| 版本化 | 每个版本有明确的变更记录 | 知道 v0.1 和 v0.2 的差别吗？ |
| 更新成本 | 更新一条判断是否牵一发动全身 | 发现一个错误，改起来费劲吗？ |

### 维度四：边界意识（Boundary Awareness）
*对应: 原始组件（Psyche 特有）*

| 子维度 | 定义 | 自检问题 |
|--------|------|---------|
| gap 明确 | 未覆盖区域有具体列表 | 这个 Psyche 不能回答什么问题？ |
| 置信度标注 | 每条判断标 L1-L4 | 我知道哪条判断是推测的吗？ |
| 时效标注 | 覆盖到什么时间点的知识 | 最后更新是半年前吗？需要刷新吗？ |

### 评分方法

每个子维度 1-5 分（参照 OQuaRE 5 级评分）：

| 评分 | 含义 | 判断标准 |
|------|------|---------|
| 1 | 不可接受 | 基本没有做到 |
| 2 | 需改进 | 有但严重不足 |
| 3 | 最低可接受 | 及格线，可使用但需留意 |
| 4 | 可接受 | 质量达标，无明显问题 |
| 5 | 超出要求 | 做得非常好，可以当作典范 |

## 三、构建方法论 — 四阶段高质量执行指南

遵循现有构建协议（psyche/工具/构建协议.md）的四阶段流程，但在此之上增加"每个阶段怎么做才质量高"的指导。

### 阶段〇：工作量校准

> ⚠️ **关键前提**：以下估算以"我（agent）的工作速度"为基准，不是"人的阅读速度"。
> 我读一篇摘要 = 几秒（一次 tool call），读全文 = 几十秒。但思考、交叉验证、写卡片是真正的时间消耗。

**目标**：动手前先拆实际工作量，不套模板数字

**我的时间消耗公式**：
```
总时间 ≈ Σ(工具调用次数 × 单次耗时) + 思考决策时间 + 文件写入时间
```

**影响工作量的三个独立维度**：

| 维度 | 解释 | 对我的影响 |
|------|------|----------|
| **材料广度** | 要读多少篇材料 | 主要影响搜索/读取类工具调用次数（秒级） |
| **思考深度** | 需要多深的判断和蒸馏 | 主要影响 think 次数和决策时间（分钟级） |
| **落盘量** | 要写多少文件 | 主要影响 write_file 次数（秒级） |

**思考深度三档（真正的时间瓶颈）**：

| 深度 | 含义 | 典型工具调用 | 典型耗时 | 适用于 |
|------|------|-------------|---------|--------|
| **扫读** | 了解有什么、结构是什么，不深究细节 | 3-8 次（search + read 摘要） | 30s-2min | 初步调研、外围材料、已有基础时的补充 |
| **通读** | 读全文/核心内容 + 提取关键发现 + 形成判断 | 5-15 次（search + read 全文 + think + 写笔记） | 2-10min | 核心子领域的代表作、需要理解因果结构 |
| **研读** | 逐篇精读 + 交叉验证 + 与已有知识对比 + 完整卡片 | 15-30+ 次（多源读取 + 对比 + think + 多文件写入） | 10-30min | 奠基性工作、有矛盾需要辨别的论文、需要更新核心判断 |

**工作量估算步骤**：

1. **估算材料广度** — 列出所有需要读的材料清单，按领域类型分类
2. **对每份材料标思考深度**（扫读/通读/研读）——**这是最关键的一步，不标≈没估**
3. **估算落盘量** — 大致写几个文件（1 张大卡片 vs 3 张卡片 + 更新链接等）
4. **参考典型场景耗时**：

| 场景 | 材料广度 | 思考深度 | 落盘量 | 典型总耗时 |
|------|---------|---------|-------|----------|
| **补充已有 Psyche**（如 v0.2→v0.4 补 CommonKADS+LLM-era KE） | 3-5 篇框架材料 | 扫读为主 | 2 张卡片 + 更新核心 | 2-5min |
| **构建外部领域 Psyche**（如自动驾驶，L2 扎实版） | 10-20 篇论文 + 2-3 综述 | 3-5 篇通读，其余扫读 | 5-10 张卡片 + 核心 + 地图 | 20-40min |
| **构建外部领域 Psyche**（L3 完整版） | 20-40 篇论文 + 综述 | 5-10 篇研读，10 篇通读 | 10-25 张卡片 + 全套文件 | 40-90min |
| **构建元领域 Psyche**（如 psyche-building 初始版） | 2-5 篇框架文献 + 实证整理 | 扫读为主 | 5-8 张卡片 + 核心 | 5-15min |

5. **上浮缓冲**：复杂任务（跨模块接线、需深度研读）上浮 1.5-2x
6. **对标**：引导流程 L1/L2/L3 参考值，确认偏差是否合理

**材料选择三原则**：
- **最有名的** — 该领域最常被引用的 2-3 篇经典文献必须读（综述、奠基性工作、开创性方法论），不可跳过
- **最新的** — 覆盖 2025-2026 的最新进展，确保认知框架不基于过时知识
- **学完立即落盘** — 每读一篇必须存 knowledge/ 卡片，不存等于没读

**常见失败模式**：
- ⚠️ **用人的阅读速度代入** — 这是"你是我"的根本性错误。我的"读"是 tool call，几十秒解决。人的"读"是半小时起步。用人的速度估我的工作量 = 永远严重偏高
- 用模板数字替代实际工作量拆解 → 严重偏差
- 不标思考深度 → "5 篇材料"每篇是扫读还是研读差 10 倍以上
- 跳过经典只读最新 → 不知道根源
- 跳过一个完整子领域认为"知道大概" → 留下认知盲区

**高质量标记**：能说清"这个 Psyche 为什么需要 X 小时，以及 X 是怎么拆出来的"。

### 阶段一：全景测绘的高质量执行

**目标**：不是"搜到几篇综述"，而是"建立起对领域的结构化理解"

| 步骤 | 高质量做法 | 常见失败模式 |
|------|-----------|-------------|
| 搜综述 | 找 2-3 篇**权威的、不同角度**的综述（注意不是同质化来源） | 只搜一篇最火的，其他都是引用它的 → 视角单一 |
| 搜最新 | 搜 2025-2026 最新论文确保不基于过时知识 | 只读经典不读最新 → 领域已完成范式转移都不知道 |
| 读综述 | **读全文**，不只读摘要。确定子领域列表、时间线、open challenges | 只看摘要就画地图 → 细节全是猜的 |
| 交叉验证 | 不同综述的矛盾点记录下来 | 都是权威或相信权威 → 矛盾被忽略 |
| 落盘 | 每读一篇立即存 knowledge/ 卡片（ analyze_paper → save_paper_card ），包含三问：解决了什么？隐藏假设？留下什么新问题？ | 读了觉得"我知道了"就不存 → 下一会话重查 |
| 采实践 | 从已有项目实践中提取经验（比文献更直接） | 只看文献不碰实践 → 脱离真实约束 |

**关口检查（来自构建协议阶段一）**：
1. 能不翻资料说清子领域拓扑 + 近3年最大变化？
2. `knowledge/{领域名}/` 目录已建立？
两项同时满足才能推进到阶段二。

**高质量标记**：能画出领域拓扑图 + 说出最近 3 年最大变化 + 知道几篇综述的分歧点。

### 阶段二：深度浸泡的高质量执行

**目标**：不是"读了多少篇"，而是"读懂了因果结构"

| 步骤 | 高质量做法 | 常见失败模式 |
|------|-----------|-------------|
| 选论文 | 每个子领域选代表论文——奠基性、转折点、最新、争议性，四类都要 | 只读最新不读经典 → 不知根源 |
| 读论文 | 读全文，三问：解决了什么前人没解决的？隐藏假设是什么？留下了什么新问题？ | 读摘要就当读完了 → 理解停留在表面 |
| 存卡片 | 读后立即存 knowledge/（ analyze_paper → save_paper_card ）| 读了觉得"我知道了"就不存 → 下一会话重查 |
| 交叉链接 | 新论文与已有 Psyche 判断做对比：支持、矛盾还是新增 | 单篇孤立存储 → 没有建立联系 |
| 做注释 | reading-log 标注核心发现 + 对 Psyche 的影响 | 只记录"读了"不记录"学到了什么" |

**关口检查（来自构建协议阶段二）**：
1. 能画出 5 年技术演进图，标出转折点原因？
2. 所有代表性论文已通过 `save_paper_card` 存入 `knowledge/{领域名}/`，阅读日志记录了卡片位置？
3. 每张卡片有完整阅读笔记（三问：解决了什么？隐藏假设？新问题？）？
三项同时满足才能推进到阶段三。

### 阶段三：因果蒸馏的高质量执行

**目标**：从 N 篇论文、N 条经验中提炼出 1-2 页核心框架

| 步骤 | 高质量做法 | 常见失败模式 |
|------|-----------|-------------|
| 回看四问 | ①因果链（真实驱动力是什么？）②判断准则（什么算好工作？）③负面知识（什么试过但失败？）④边界（共识 vs 争议？） | 直接写核心不回顾 → 遗漏关键因果 |
| 写认知姿态 | 每个不动点基于具体经验/文献，不编 | 姿态空洞 → "知识很重要"之类废话 |
| 写判断准则 | 每条准则标注来源 + 证据等级 | 不标注 → 3 个月后不知道这条哪来的 |
| 标简洁性 | 写完检查：去掉这条准则，理解是否受影响？如果不受 → 删 | 堆砌准则 → 太多记不住，等于没有 |
| 做链接 | 每个判断标 → knowledge/ 卡片路径 | 不链接 → 不可追溯 |

**关口检查（来自构建协议阶段三）**：
1. 核心给领域研究生看 → "这人真的懂"？
2. 核心中每条判断标注了 `knowledge/` 路径？无卡片支撑的标了 L3/L4？
两项同时满足才能推进到阶段四。

### 阶段四：验证迭代的高质量执行

| 类型 | 问题 | 置信度标注 |
|------|------|-----------|
| 基础问题 | 这个领域现在还有什么好做的？ | 基于知识还是推测 |
| 挑战问题 | 某个热门方法有什么问题？ | 基于知识还是推测 |
| 边界问题 | 单人资源能做什么不能做什么？ | 基于知识还是推测 |
| 对抗问题 | 别人说XX方向好，我的独立判断是什么？ | 基于知识还是推测 |

**高质量标记**：回答有结构、有分层信心、有来源标注。

## 四、评估演化 — 自检、更新与退化信号

### 自检清单（每次构建完成必做）

#### 🔴 执行底线预检（三条都不满足→不算可用psyche）

```
[ ] `knowledge/{领域名}/` 目录存在？
[ ] 阅读日志中所有代表性论文有对应卡片？
[ ] 核心中每条判断可追溯到 `knowledge/` 具体文件？（无卡片支撑的判断已标 L3/L4）
```

任何一条不达标→退回补完再做详细自检。

#### 详细自检

```
[ ] 功能覆盖
   [ ] Competency Questions 全部有对应判断覆盖？
   [ ] 每条判断有 knowledge/ 卡片支撑？
   [ ] 判断准则可操作（别人能用它做决定）？

[ ] 结构质量
   [ ] 判断准则之间无矛盾？
   [ ] 没有冗余判断（去掉一条不影响整体）？
   [ ] 层次清晰（认知姿态→地图→准则 递进）？

[ ] 可演进性
   [ ] 支持子 Psyche 扩展？
   [ ] 版本号 + 变更日志？
   [ ] 单条判断更新成本低？

[ ] 边界意识
   [ ] reading-gaps 有具体未读列表？
   [ ] 所有 L3/L4 判断明确标注？
   [ ] 时效标注（覆盖到什么时间）？

[ ] 工作量估计
   [ ] 时间估算是按阅读量拆解算的，不是照搬模板？
   [ ] 领域类型判断正确（外部/元/技术栈）？
   [ ] 缓冲余量留够了？

[ ] 学习覆盖度
   [ ] 该领域最有名的经典文献读了？（综述、奠基性工作、开创性方法论）
   [ ] 最新进展（近1-2年）覆盖了？
   [ ] 每篇读后都存了 knowledge/ 卡片？
```

### 更新触发条件

| 信号 | 动作 | 紧急度 |
|------|------|--------|
| 读到的新论文与核心判断矛盾 | 立即更新核心（先存卡片，再改判断） | 🔴高 |
| 新论文补充但未矛盾 | 存卡片，核心标"有补充材料" | 🟡中 |
| 已经 3 个月没更新 | 检查 reading-gaps 是否需要刷新 | 🟡中 |
| 使用中发现判断准则不够用 | 加新准则（经过卡片支撑） | 🟡中 |
| sub 新增 Psyche | 检查父 Psyche 是否需要调整 | 🟢低 |

### 退化信号（Psyche 需要重建而非修补）

| 信号 | 判断标准 |
|------|---------|
| 核心膨胀 | 读一遍超过 5 分钟 → 需要重新蒸馏 |
| 矛盾积累 | 3 条以上判断准则相互矛盾 → 需要重构因果链 |
| 边界模糊 | reading-gaps 写成"待补充"而不是具体列表 → 需要重新全景测绘 |
| 来源断裂 | 超过 30% 的判断无法追溯 → 需要补卡片或降级 |
| 领域剧变 | 领域出现颠覆性变化（如新范式）→ 需要重新从阶段一开始 |
| 持续估算偏差 | 连续 2 次以上实际耗时与估算偏差 > 3x → 说明工作量校准环节失效，需要重新分析领域类型分类是否正确 |

## 五、外部学习与 Psyche 进化循环

从外部获取知识 → 学透 → 落盘 → 更新 Psyche → 自检 的完整回路。

### 触发信号

以下情况自动触发一次学习-进化流程：

| 信号 | 紧急度 | 动作 |
|------|--------|------|
| 遇到有价值的项目/论文/工具 | 🟢 低 | 下载/克隆，按流程学透 |
| 用户说"你去学一下XXX" | 🔴 高 | 立刻启动流程 |
| 已有 psyhe 超过 3 个月未更新 | 🟡 中 | 检查 reading-gaps 是否需要刷新 |
| knowledge/ 积累超过 psyche 核心的覆盖范围 | 🟡 中 | 评估是否需要更新核心 |

### 流程四步

#### 第一步：素材获取与范围界定

```
触发信号 → 确定学什么
   ├── 项目（clone 到 D:\agent_git/）
   ├── 论文（scan_papers/scan_conf → read_paper）
   ├── 工具/文档（search_web → read_page）
   └── 其他（按需处理）

同时做：
  确定这个素材属于哪个现有 psyche 的覆盖范围
  如果没有对应的 psyche → 考虑新建（走四阶段构建流程）
```

**关口：** 明确了这个素材「属于哪个 psyche」「为什么要学它」「学到什么程度算够」。

#### 第二步：深度阅读与分析

不是扫读概要，是把项目/论文/文档**拆开看**：

**项目类（代码）**：
```
① 入口在哪里？包/模块怎么分的？
② 核心架构是什么？（模块依赖/数据流/控制流）
③ 关键决策是什么？（为什么这么设计，留下了什么 trade-off）
④ 失败模式在哪？（什么场景下会崩、什么配置会踩坑）
⑤ 和我们的对比：哪些直接可用、哪些有参考价值、哪些不合适
```

**论文类**：
```
三问：解决了什么前人没解决的？隐藏假设是什么？留下了什么新问题？
方法论分类（6种类型）
与已有 knowledge/ 交叉验证：支持、矛盾还是补充
```

**关口：** 能说清「它的核心思想是什么」「它最好的地方是什么」「它的问题是什么」。  
**🔴 不可跳过的纪律：** 读了必须和已有 knowledge/ 卡片做对比（支持/矛盾/补充），不能孤立存储。

#### 第三步：落盘与 Psyche 联动

```
① 写 knowledge/ 卡片（完整笔记，含三问/对比/关键发现）
② 检查对应的 psyche：
   - 现有 psyche 够用 → 更新 reading-log，标注新卡片位置
   - 现有 psyche 需要补充 → 更新核心（蒸馏有价值的判断准则）
   - 没有对应 psyche → 走四阶段构建
③ 更新 reading-gaps（已覆盖/部分覆盖/未覆盖）
④ 更新 knowledge-links（新判断 ↔ 新卡片）
```

**关口：** 卡片存了，psyche 核心更新了（需要时），reading-gaps 和 knowledge-links 同步了。

#### 第四步：全面自检

用本 psyche 四章的自检清单做一次全面检查（见四、评估演化 → 自检清单）。

重点检查项：
```
[x] 新学的内容和已有 psyche 判断有没有矛盾？（一致性检查）
[x] 新判断有没有知识库卡片支撑？（来源检查）
[x] 有没有更新 reading-gaps + knowledge-links？（同步检查）
[x] 现有 psyche 的版本号是否正确递增？（版本检查）
```

**关口：** 自检全部通过 → 提交。  
**🔴 不可跳过的纪律：** 每次更新 psyche 后必做自检，不自检不提交。

### 进化四步与自检清单的对应关系

| 流程步骤 | 在自检清单中对应的检查项 |
|---------|----------------------|
| 第一步：素材获取 | → 学习覆盖度：经典/最新都覆盖了？ |
| 第二步：深度分析 | → 交叉验证：与已有知识对比了？→ 一致性检查：没有矛盾？ |
| 第三步：落盘+联动 | → 双轨制：有 knowledge/ 目录？→ 来源充分：每条判断可追溯？ |
| 第四步：全面自检 | → 完整的自检清单执行 |

## 六、负面知识

- **不要追求完美再发布** — Psyche 是演进的，v0.1 可以只有认知姿态 + 初步的判断准则。等"完美"了再发布等于永远不会发布。[→ 实证]
- **不要用 Psyche 替代知识库** — Psyche 是认知框架（怎么想），knowledge/ 是知识存储（知道什么）。混用会导致核心膨胀到不可加载。[→ 实证]
- **不要覆盖所有子领域均匀深度** — 根据用途选择重点。指导型 Psyche 需要判断准则深度，质检型需要评估维度完整。均匀覆盖 = 每个都不够深。[→ 实证]
- **不要只读一种类型的文献** — 只读学术界不看工业界 → 脱离实际约束。只读工业界不读学术界 → 看不到前沿和陷阱。[→ 实证]
- **不要在蒸馏阶段省时间** — 读论文花 5 小时，蒸馏花 15 分钟 → 核心质量取决于蒸馏投入，不取决于阅读量。[→ 实证]
- **不要用模板估算替代实际工作量判断** — 引导流程的 L1/L2/L3 时间参考是通用参考值，不是数学公式。照填 = 规划谬误。正确做法：先判领域类型（外部/元/技术栈），再拆阅读清单，再累加时间。[→ 实证: psyche-building 构建时 5-8h 估成 6min]
- **不要跳过经典只读最新，也不要只读经典不读最新** — 只读最新不知道根源（理解停留在表面），只读经典不知道领域已发生范式转移（认知框架过时）。必须两种都覆盖。[→ 实证: CommonKADS 是经典但第一次构建没读, LLM-era KE 是最新但第一次构建也没读]
- **不要读了不落盘** — "我知道了"是最危险的错觉。下一会话就是从头重查。读了就存 knowledge/ 卡片，这是不可跳过的纪律。[→ 实证: 多次在多个 Psyche 中踩坑]

## 七、核心矛盾

| 矛盾 | 说明 | 处理原则 |
|------|------|---------|
| 浓缩 vs 追溯 | 核心短才可加载，短了就丢证据链 | 核心只放判断准则，证据链在展开 + knowledge/ |
| 广度 vs 深度 | 所有子域都浅 vs 一个子域极深 | Competency Questions 指导：只覆盖问题需要的 |
| 稳定 vs 演进 | 框架稳定才能用 vs 领域一直在变 | 版本号 + 变更日志，v0.1 → v0.2 自然演进 |
| 通用 vs 特化 | 通用适用面广但不够精准 | 父子分层：父给通用判断，子给特化准则 |
