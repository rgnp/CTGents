## 领域拓扑

Psyche 构建（构建高质量认知框架的元方法论）不是一个"独立领域"，而是跨两个层面：

```
元层面（理论来源）                         应用层面（实践对象）
─────────────────                        ─────────────────
本体论质量评估 ────── 适配 ──────→       Psyche 质量标准
(OQuaRE/Gangemi)                          │
                                          ▼
知识工程方法论 ────── 适配 ──────→       Psyche 构建方法论
(Ontology 101/CommonKADS)                 │
                                          ▼
认知框架设计 ────── 提炼 ──────→       Psyche 评估演化
(Cognitive Architecture)                  │
                                          ▼
软件工程实践 ────── 实证 ──────→       Psyche 质量自检
(现有 Psyche 分析)
```

## 关键概念定义

| 概念 | 定义 | 来源 |
|------|------|------|
| **Psyche** | 一个领域的"认知状态"——加载后改变思维方式。不是工作流，不是知识库。 | 项目实践 |
| **认知姿态** | Psyche 的"不动点"——处理问题时默认的立场和视角。确定"我是谁"。 | 实证 |
| **判断准则** | 可操作的决策框架——面对具体问题时怎么判断好坏。"怎么做"而非"知道什么"。 | Ousterhout + 实证 |
| **证据等级** | 每条判断的置信度标记——L1经典共识/L2单一权威/L3推理/L4推测。 | Ousterhout + 实证 |
| **负面知识** | 知道什么不该做、为什么失败、什么条件下会再失败。 | 实证 |
| **reading-gaps** | 显式标注已知的未覆盖区域——知道自己不知道什么。 | 实证 |
| **双轨制** | Psyche 核心（判断准则）+ knowledge/（原始证据）同时构建。 | 构建协议 |
| **Competency Questions** | 构建前列出的"这个 Psyche 应该能回答什么问题"，用来界定范围。 | Ontology 101 |

## 关键时间线

| 时间 | 事件 | 对 Psyche Building 的影响 |
|------|------|--------------------------|
| 1995 | Gomez-Perez 提出本体论评估标准 | 建立了 Consistency/Completeness/Conciseness/Expandability 四维评估 |
| 1996 | Uschold & Gruninger 本体论方法论 | 提出本体构建的规范方法 |
| 2001 | Ontology Development 101 (Noy & McGuinness) | 标准化的迭代构建流程 |
| 2005 | ISO SQuaRE (25000) | 软件质量评估标准 |
| 2006 | Gangemi 本体论评估方法论 | 提出了本体论评估的结构化方法 |
| 2011 | OQuaRE (Duque-Ramos) | 将 SQuaRE 适配到本体论领域 |
| 2024 | KE Reference Architecture (arXiv 2404.03624) | KE 标准化架构 |
| 2026 上 | Psyche 项目实践经验 | 实证基础 |

## 核心矛盾和权衡

| 矛盾 | 两端 | 平衡点 |
|------|------|--------|
| 浓缩 vs 追溯 | 核心太短缺证据 / 太长不能加载 | 核心只放判断准则，证据链在展开 + knowledge/ |
| 广度 vs 深度 | 覆盖全但不深 / 一个子领域很深但忽略其他 | L1-L3 分级决定，按用途选择 |
| 稳定 vs 演进 | 框架稳定才能用 / 领域在变 | 版本号 + 更新日志，不追求"最终版" |
| 通用 vs 特化 | 通用框架适用面广但不够精准 | 父子 Psyche 分层，通用在父、特化在子 |
