# 领域 Psyche 加载协议

## 触发条件

用户明确说出领域名，或任务内容明显属于某个已建 psyche 的覆盖范围。

## 加载步骤

```
Step 1: 确认覆盖范围
  读 psyche/{领域名}/索引/{领域名}.md
  检查：时效性是否过期？覆盖范围是否匹配当前问题？

Step 2: 注入认知框架
  读 psyche/{领域名}/核心/{领域名}-core.md
  这是改变思维质地的核心——必须读入当前工作上下文

Step 3: 知晓阅读边界
  读 psyche/{领域名}/阅读索引/reading-log.md（最近更新）
  读 psyche/{领域名}/阅读索引/reading-gaps.md
  知道读了什么、没读什么——知道自己的认知边界

Step 4: 验证证据完整性（知识持久化检查点）
  对照核心中的判断引用，检查 knowledge/{领域名}/ 下对应的卡片是否存在
  如果核心声称"读过某篇文章"但 knowledge/ 中无卡片 → 标记为"待补"并记入任务
  核心中标注 L1/L2 的判断，必须有对应的 knowledge/ 卡片支撑

Step 5: 链接知识库
  读 psyche/{领域名}/链接/{领域名}-knowledge-links.md
  知道判断依据存在哪

Step 6: 钉住关键约束
  pin("Psyche加载: {领域名} v{版本}, 四级证据等级+知识卡片追溯", durable=true)

Step 7: 生效
  所有该领域的判断以核心框架为基准
  输出中的事实断言标注来源（→ knowledge/ 具体卡片）
  超出阅读边界的部分，标注推测及置信度
  核心引用但 knowledge/ 中无卡片的判断 → 降级为 L3/L4
```

## 卸载

```
Step 1: unpin(当前 psyche 相关 pin)
Step 2: 检查是否有认知更新：
        - 有新知识 → 更新 reading-log.md
        - 有认知结构变化 → 更新 core.md 或 展开/
Step 3: 标记卸载完成
```

## 冲突处理

AGENTS.md 的可信验证流程、三问方法论、安全规则 → 永远优先于 psyche。
psyche 中的判断准则 → 在领域范围内优先于 AGENTS.md 的通用方法论。
